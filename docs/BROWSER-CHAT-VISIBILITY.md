# 打开聊天后放下完成牌

macOS 修复版按屏幕上实际露出的聊天判断：聊天放在外接屏时，在另一块屏幕操作别的软件也可以放下对应完成牌。完全遮住、最小化、隐藏、移到其他桌面的窗口不算；只露出标题栏或窄边不算。新一轮没看到的回答仍会举牌。

## 为什么之前失效

- 已安装的 0.4.2 没有包含之前单独提交的网页和插件识别。
- 旧逻辑只检查最前面的软件，不能满足同时使用两个屏幕的情况。
- App 里的聊天选择记录被当成十秒后过期，停留阅读时也会失效。
- 当前 GPT Chrome 插件直接显示聊天，没有普通聊天网页的地址，旧网页判断无法识别它；顶部按钮还有多层包裹。
- 程序坞有一块覆盖整屏的透明区域，旧判断误以为它挡住了主屏聊天。现在只排除这类透明区域，普通窗口仍参与遮挡判断。
- Claude App 需要先启用它自带的界面信息支持，且当前聊天使用的地址与网页不同；现已补上。

## 当前识别范围

- 网页及 Claude 插件中的聊天文档：使用聊天地址与已跟随会话准确对应。历史列表、消息里的链接、后台标签不算。
- GPT App：可读取的当前聊天文档完整标题先尝试唯一对应（同名限制与插件相同）；系统确认聊天窗口实际可见后，结合本次 App 运行的聊天选择记录；安静阅读不再受十秒限制。没有可靠地址且存在多个主窗口时保留牌子，不猜窗口对应关系。
- 官方 GPT Chrome 插件：仅读取顶部当前聊天按钮；在已跟随的 GPT 会话中按完整标题唯一对应。重复、截断、空白、新聊天标题不确认。未跟随会话恰好同名仍是此回退方式的限制，不能声称绝不误认。
- Claude App：启用其界面信息支持后，读取准确聊天文档地址（包括 `/epitaxy/local_…`），通过本机保存的对应关系连接到正在跟随的聊天；不再仅凭“上次选过哪条”清除牌子。没有准确可见文档时保留提醒。
- 无法与雪绪正在跟随的会话对应的纯网页聊天，不会凭名字猜测。

macOS 网页和插件需要系统的“辅助功能”允许。在雪绪设置中点击“启用浏览器自动放牌”。没有允许时 App 可用的单窗口记录仍会尝试识别，网页和插件保留牌子。

只读取窗口位置、聊天地址和官方插件顶部标题，不发送消息或点击聊天。窗口位置使用所有屏幕的共同坐标，支持外接屏在主屏左、右、上、下；通过前方窗口遮挡判断聊天区域是否真正露出。

## 核验记录（0.4.3）

2026-10-11：macOS 自动检查 203 项通过。实际双屏检查已覆盖 GPT 插件打开、关闭、重新打开、最小化、恢复、移到 Mac 自带屏幕、整个浏览器被盖住、只盖左侧网页、只盖右侧聊天。判断结果符合预期；GPT App 的当前标题经用户核对，安静阅读超过十秒仍能识别。另一条聊天的牌子在插件开关和最小化检查中保留。

GPT 普通网页、Claude 网页和插件已读到实际聊天地址；Claude App 已读到当前聊天的专用地址，并核对本机保存的聊天对应关系。最终桌面测试版已连续三次认出 Claude App 当前地址，并同时确认另一块屏幕的 GPT 插件对应聊天。这些是聊天识别证据，不等同于每一种情况下都实际观察到了牌子从举起到放下。放牌、保留其他提醒、看过不重复提醒、新回答仍提醒的规则另有自动检查。

没有逐项验证的情况：每一种 App/网页/插件的真实牌子变化、拔插显示器、睡眠唤醒。同名标题回退也有上述限制，不能保证任意情况都无问题。

Windows 代码在 Mac 上执行 263 项检查、其中 1 项跳过；发布流程另在 Windows 环境执行打包和原生窗口检查；本轮仍使用此前的前台窗口判断，未宣称具有本次 macOS 双屏修复或 Windows 实机通过。

运行中的雪绪在 `~/Library/Application Support/YukioPlayer/chat-visibility-status.json` 写入当前屏幕数、权限状态、确认的会话编号、仍举牌的会话编号及读取到的聊天地址，供本机核验，没有聊天正文。详细现场记录留在本机，不上传私人聊天地址。
