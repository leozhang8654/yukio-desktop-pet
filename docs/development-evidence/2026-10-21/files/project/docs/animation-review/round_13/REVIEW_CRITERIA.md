# 雪绪多个动画状态：纯第三方整体审查标准

你没有参与制作，也不应了解制作过程。不要读取 HANDOFF、生成脚本、制作聊天、返工理由或此前评分。只允许查看本任务提供的评审标准和整体审查包。你只负责评判，不修改图片、动画、代码或参数。

## 目标

保留原有 Cloud 动作含义、姿势、道具、构图和安静桌面宠物风格，只进行自然化完善。动作不必夸张复杂，但必须摆脱同步、机械、幅度不可见和“同一木偶换道具”的感觉。拖动不在本轮范围内。

## 本轮用户目标

尽量复刻 Claude 原动作的节奏和幅度，保留已确认的新画风、接缝修复和自然眨眼。不要要求放大到上限或重新设计动作。以 192×208 的原版对照和动作可读性判断；主线回到原版约 2～12 秒的不同节奏。拖动不改。

## 审查顺序

1. 首先打开 `live.html` 的无标签 192×208 模式，点击播放，至少观看至 48 秒。不要提前显示标签、单独状态或标签映射。也提供 `unlabeled.html` 和 `unlabeled-192x208.mp4`；如果内置浏览器的视频播放不兼容，请使用直接播放送审图条的 live.html，不得因此用静态截图冒充连续观看。
2. 按行从左到右记录能否通过动作大致判断打字、写字、核对、阅读或查看图片，以及判断依据。
3. 连续观看至少三轮，检查同步眨眼、同步停顿、相同节拍。
4. 然后查看有标签版本 `index.html`，核对动作含义。
5. 查看每个状态的实际尺寸三轮视频；192×208 为判断幅度的主要依据，200% 只辅助检查边缘。
6. 查看 200%、动作极限帧、连续帧、整幅接触表及黑、白、洋红、棋盘格背景。
7. 查看 `state-transitions.mp4`，检查状态切换。完成无标签和单状态检查后，还可查看 `preview.html` 中各状态原版对照；前后图条都封装在本审查包内，使用同一时间轴。检查本轮动作是否接近原版节奏与幅度，同时仍然自然、连接可靠。
8. 最后读取各状态 validation.json、native-validation.json、overall-validation.json、timing-table.json 和动作强度曲线，只用于交叉验证，不能代替目测。

## 评分，共 100 分

- 整体自然度与节奏差异：20 分。
- 各状态动作辨识度：20 分。
- 192×208 实际尺寸可读性：15 分。
- 手、道具、目光、头部和身体的配合：15 分。
- 眨眼、双眨和停顿的自然程度：10 分。
- 所有状态之间的画风与角色一致性：10 分。
- 接缝、毛边、变形、跳帧等技术质量：10 分。

## 任意一项出现即直接退回

- 多个状态明显在同一时间眨眼或停顿。
- 大量状态具有相同周期和相同动作曲线。
- 主要动作只有在 200% 放大后才能看见。
- 写字、核对、查看图片等状态只能依靠道具区别。
- 为增加区别而大幅破坏原有 Cloud 动作或构图。
- 手臂断开、道具漂浮、描边缺失、透明毛边或背景残留。
- 未活动的脸、身体、桌椅或背景发生变形。
- 动画首尾跳变或状态切换明显闪动。
- 眨眼过于规律、频繁、同步或出现虹膜残留。
- 缺少足够的实际尺寸动画，无法可靠判断。

## 通过条件

必须同时满足：无强制退回项；总分至少 90；能明确确认原动作含义保留；整体自然，不像一批同步机械人；明确写出“整体评审通过”。否则必须退回。

## 返回格式

结论：整体评审通过 / 退回

总分：XX/100

逐项评分：列出上述七项得分。

无标签辨认结果：逐个说明认为在做什么，以及动作判断依据。

整体问题：说明是否同步、机械重复、幅度过小或同一木偶换道具。

具体问题：必须写明状态、画面位置、时间点或帧号、严重程度和可执行修改建议，不能只写“感觉不自然”。

实际检查材料：列出看过的预览、背景、尺寸、速度和关键帧。

不要因整体可爱而忽略局部问题，也不要因动作简单而要求夸张表演。判断重点是在保留原动作的情况下，自然、清楚，并且彼此不机械同步。
