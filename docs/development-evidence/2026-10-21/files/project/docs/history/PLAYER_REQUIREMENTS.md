# 独立播放器：下一阶段工作

这是待实现的工程要求和建议，不是已实现的功能清单。

## 1. 单角色播放器

- 始终只显示一个雪绪实例，通过状态选择动画，不创建不同宠物或不断销毁重建窗口。
- 目标 macOS：透明背景、置顶、可拖动、合理的鼠标命中区域；退出方式与运行状态清晰可见。
- 拖动时复用原版左右跑动；停止拖动后回到当前活动，不误切成其他角色。
- 按资源原始宽高比绘制；桌腿和落脚点有固定锚点；避免整个图像缩放呼吸。
- 加载资源后再切换，禁止出现空白一帧、背景色闪现、图格越界或残影。
- 递交报告播放一次后保持，再由新的活动或空闲事件结束。

## 2. 活动事件与适配层

先定义独立于 Codex 的小型事件协议，再验证具体可用的事件来源。建议字段包括：时间戳、会话 ID、活动 ID、事件 ID、开始／结束／取消阶段，以及可选的工具名称。

上述字段是拟定协议，不能声称 Codex 已提供这个接口。先使用可重复的模拟事件；真实接入应单独验证来源、时延、顺序、工具执行完成与任务结束语义。

不要把所有 exec 命令都当作测试，也不要把图中“已运行／已查看”的历史文本误认为仍在进行的活动。读取、写入和测试可能共用同一个终端工具，需要明确的语义标注或有限、可验证的分类规则。无法确定时回默认电脑桌。

思考与整理回答的信号可用性也需要单独确认；普通 commentary 更新不能直接等同于最终输出。多个任务同时运行时，需要明确跟随哪个任务，避免交叉串状态。

## 3. 防抖与调度

建议起点：活动稳定 400 ms 后生效（可调 300–600 ms），每个活动至少展示 1500 ms（可调 1–2 秒）。这些是待调参数，不是用户指定的精确数值。

- 合并同类短事件，短于防抖窗口的活动不应逐个闪现。
- 保持时间内只保留最后一个有效候选，旧事件不可在队列里排长队。
- 当前活动持续时不能因为动画循环结束而强制回待机。
- 未知且仍在工作的活动用电脑桌；明确空闲用基础 idle。
- 工具结束、失败、取消、连接丢失与新任务开始要有清晰的状态清理。
- 动作间可以使用短过渡，但先检查不同姿势叠化的双重轮廓问题，不要用模糊掩盖几何错误。

## 4. 建议实施顺序

1. 核对素材，运行包校验，复用 HTML 演示了解当前序列。
2. 选择桌面技术栈并搭建单窗口播放器；将资源索引和状态控制独立成模块。
3. 用模拟活动事件驱动状态，完成时序、结束保持和未知事件回退。
4. 用可控制的时钟验证防抖、最短保持、快速交替、取消、乱序及多任务隔离。
5. 调查并接入实际 Codex 活动来源。接口不存在时说明真实阻碍，不把模拟接入当作完成。
6. 在本机 macOS 验证透明、置顶、拖动、多显示器、缩放、CPU 占用和退出；再交付可运行版本。

Cloud 中能先做可移植模块、事件模拟、测试与构建配置；macOS 专属行为必须回本机验证。不要无依据承诺在 Linux Cloud 中已完成 macOS 实机验收。

## 5. 验收清单

- 只有一只雪绪；没有七个宠物条目。
- 七个活动 ID 各自显示选定动作；未知工作显示电脑桌。
- 连续快速事件不会让动作频繁闪跳；同类活动不反复从头重播。
- 平板使用的是修正图，手指在屏幕正面；原版左右跑动仍可用。
- 人物比例、桌椅几何、落脚锚点稳定；不出现旧跳跃或欢呼变形。
- 报告递出后停留，不循环往返。
- 真实事件接入与模拟演示能清楚区分；断连后不会永久卡在失真的活动状态。
- 文件路径相对工程，资源随应用打包；不依赖原电脑的绝对路径。
