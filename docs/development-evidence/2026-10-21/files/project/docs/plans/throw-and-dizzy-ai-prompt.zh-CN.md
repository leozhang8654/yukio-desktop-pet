**1. 你的目标与任务边界**

为雪绪桌宠新增完整交互：拎起并晃动 → 松手抛出或自由下落 → 撞到屏幕边缘后失速反弹 → 落到屏幕底部 → 缓冲、晕眩 → 恢复当前任务动作。Mac 与 Windows 采用相同规则、参数和素材。轨迹由实时物理状态决定，撞击表演由碰撞事件驱动。

保留已确认的角色身份、画风、身体比例、衣服、现有动作语义和日常头颈固定方案。新交互优先使用无桌子的全身形象，不能把工作桌、纸张、任务卡一起当作角色抛出去。第一版实现平面运动和有限倾斜；不要求自由翻筋斗、布娃娃关节或 3D 模型。

默认交互规则：

- 开启「抛掷互动」时，真正拖拽后松手都受重力影响；轻松手也会下落，不能偷偷回到旧的悬空摆放行为。纯点击、右键和 control-click 不抛掷。设置关闭后保留原有拖动摆放。
- 用松手时所在显示器的完整矩形作围墙；左右、顶边有碰撞，底边是地面。多屏第一版将每块显示器看作独立房间，拖动可跨屏，松手后锁定选中的那一屏，下一次抓取可重新选屏。此为本计划的产品默认值，不声称用户已经逐项确认。
- 每次实际落地均有可辨认的轻重反应及晕眩，普通落地约 1.6 秒晕眩加 0.4 秒恢复；轻放缩短，重摔稍延长。弹跳未停稳时先表现撞击，站稳后开始完整晕眩，不在半空里站着摇头。
- 飞行、反弹、晕眩、恢复过程中都能再次抓住。再次抓住立即终止自动飞行，抓取首帧的位置和姿态连续；新的松手只用本次手势数据。
- 恢复后留在落点，恢复当时最新的活动状态；不回传到抛出位置，不恢复已经过期的任务状态。

**4. 先设计可复现的数据与状态接口**

建议新增纯逻辑模块 ThrowPhysics.swift / throw_physics.py，以及 DragVelocityTracker.swift / drag_velocity.py；命名可依仓库规范调整。平台层只负责输入、时钟、屏幕转换、窗口和呈现，物理核心不得直接访问鼠标或窗口 API。

共享参数文件保存版本、单位、默认值；共享轨迹 fixture 保存初始状态、带时间的输入、屏幕矩形、缩放、预期碰撞与状态变化。两种语言读取同一份数据，避免手抄两套常量。

核心至少包含：position、velocity、gravity、interactionPhase、screenID、collider、groundContact、lastImpact、throwSessionID、elapsedInPhase；视觉另含 angle、angularRate、pose、expression、effectTime。碰撞事件包含 eventID、接触时刻、normal、contactPoint、碰撞前法向速度和强度。相同接触不能每一帧重复发事件。

交互状态与 AI 活动状态分开：

    Normal --超过拖动阈值--> Held --释放--> Airborne
    Airborne --撞墙/顶--> Airborne + ImpactEvent
    Airborne --触地且仍会反弹--> Airborne + LandingImpact
    Airborne --保持地面接触且速度收敛--> Dizzy
    Dizzy --时间结束--> Recover --完成--> Normal（最新活动）
    Held / Airborne / Dizzy / Recover --重新抓取--> Held

抓取已有动作时，拖拽判定和首帧姿态继承要同时正确。可在按下命中飞行角色时暂时抓稳并保存快照；达到拖动阈值进入 Held。若按下后未拖动，则消费为一次抓稳／接住动作，不顺便打开聊天，也不留下永久暂停；释放后按当前高度进入安全的低速下落。Normal 下原有单击行为不变。

碰撞只发局部反应事件，不能把顶墙或侧墙当作地面进入 Dizzy。地面多次回弹记录最高／最近有效撞击强度，最终只启动一次晕眩段。

**5. 鼠标释放速度与钟摆交接**

- 按输入事件时间采集最近约 100 ms 的全局指针样本；可调范围 80–120 ms。使用单调时钟，以秒计物理时间，明确与现有毫秒时间线的转换。
- 加入松手的最终位置和时间。对最近样本做带时间权重的线性拟合，求 x、y 斜率；不只用最后两点，不用整段拖拽平均。丢弃重复时间、非有限值，短样本给出明确降级行为。
- 鼠标停住时可能不再发 move 事件。依据最后有效移动距释放的间隔衰减旧速度；超过约 120 ms 视为手已停。对反向甩动保留最近方向，不能被早期方向拉回去。
- 不用窗口原点计算释放速度：拎起窗口扩张、DPI 改变、边缘校正都不是用户加速。跨屏拖动时先统一坐标；屏幕／DPI 重映射不能制造一个巨大的假速度。
- 松手时保持角色重心的世界位置及当前倾角。抓手到重心的向量为 r，重心初速度可由 v_hand + omega × r + 下坠偏移的世界速度得到。需暴露 HangSwing 必要的只读快照，或者直接跟踪已正确转换的重心运动；两种方法只能选一种，禁止重复叠加摆动速度。
- 为便于控制，初速度可以作有限增益、低速抑制和最终合速度限幅；对整个向量限幅，保留方向。记录哪些是手感处理，不称之为严格刚体力学。手已停但身体仍摆动时，可保留温和的切向惯性。
- 旧 dragEnded 里的工作区 clamp 和立即存盘不能先运行再启动抛掷；只对已经越出所选屏幕的实体做最小必要回收。进入 Airborne 后抓手约束解除，不能一边自由落体一边继续作为吊在固定点上的钟摆。

**6. 物理规则与首轮参数**

统一仿真坐标：显示器局部的逻辑单位，x 向右，y 向上，时间为秒。Mac 使用 point，Windows 将选中显示器的物理坐标减去该屏原点再除以 DPI 比例；不要对含不同 DPI 的整张虚拟桌面直接除一个比例。资源 pixelScale 与系统 DPI、用户角色缩放是三个不同概念。

第一轮自由飞行取恒定重力、无水平空气阻力，便于检验抛物线；如后续增加空气阻力，使用依时间的衰减并记录理由。每个无碰撞子段：

    p(t+h) = p(t) + v(t) * h + 0.5 * a * h²
    v(t+h) = v(t) + a * h
    a = (0, -g)

遇墙时，n 为朝房间内的单位法线，仅当 v·n < 0 才施加冲量。分解 v_n = (v·n)n 与 v_t = v-v_n，令 v'_n = -e*v_n；切向分量只在接触摩擦作用下衰减。0 ≤ e < 1。静止接触的重力由支持约束抵消，不能每帧重力推动后再触发一轮反弹。

所有下列数值是本项目的**首轮试调值**，需要真实播放验证并落入共享配置；不属于外部来源的成品数据。

| 参数 | 起始值／范围 | 目的 |
| --- | --- | --- |
| 固定物理步长 | 1/120 s | 输入、绘制帧率变化时规则一致 |
| 积分追帧上限 | 每次最多 12 步；长间隔约 250 ms 单独处理 | 卡顿或唤醒不造成巨大瞬移和无休止追帧；明确丢弃的时间 |
| g | 2400 逻辑单位/s²；试调 1800–3000 | 500 单位高处静止下落约 0.65 s，作为计算示例，不是最终体验保证 |

角色缩放改变碰撞形状与锚点，默认不再乘一次 g 或鼠标速度；屏幕高度变化也不暗改物理参数。先验证多种分辨率上的手感，确有需要再提出独立的速度档位。

固定步长使用 accumulator，显示层插值。普通掉帧能在预算内补齐；更长卡顿暂停世界并丢弃积压时间，不补演睡眠期间轨迹。碰撞事件只从物理步输出。回弹高度在相同条件下自然递减，不强行规定每次恰好弹两次。

**7. 围墙、角色形状和连续碰撞**

先只解决一个角色与四个轴对齐静态平面的碰撞，避免做通用游戏引擎。预先标注源图中的实体外轮廓简化凸包、脚底接触点、重心和姿态锚点；明确装饰星星不属于实体。透明窗口外框、透明 padding、气泡和任务卡都不作为角色碰撞体。

各交互姿态使用一致坐标和稳定的碰撞描述。按当前旋转／局部姿态求四个方向的轮廓支持距离，再检查其对四面墙的间隙。姿态变化不得让碰撞体突然膨胀并把角色顶飞；切换时保持重心，贴地阶段保持脚底接触锚点，并将校正限于必要范围。

平移需要 swept 检测／首次接触时间 TOI：一个物理步内先推进到最早接触点，处理法向速度，再推进剩余时间。角落在时间容差内合并两个接触法线，避免左右判定反复翻转。限定每步碰撞迭代次数；耗尽时将角色放在最后安全位置并消除朝墙速度，记录诊断，不把未求解的剩余位移直接应用。

有限倾斜为表演通道，不声称是完整转动惯量模拟。它仍会改变可见轮廓，所以必须进入连续检测：用轮廓最大旋转半径和角度变化给 swept 包络加保守余量，候选接触再细分时间求证；不能只检查步首和步尾两个矩形。接近墙面可减小视觉倾角，但保持连续，不注入新的平移能量。若此几何实现无法通过防穿透测试，换成熟求解器并说明依赖与跨语言绑定成本，不靠放宽测试过关。

视觉形变不驱动物理反弹。落地屈膝／身体缓冲围绕脚底锚点，不把角色缩入地面；大头、小脚及星星留出足够透明画布。相邻屏幕之间不能用覆盖所有屏幕的大矩形，否则 L 形排列会产生没有显示器的可飞行区域。

Mac 从 NSScreen.frame 获取完整屏幕；Windows 从 MONITORINFO.rcMonitor 获取完整屏幕。完整屏幕边界与 Dock／任务栏的遮挡是两件事：不能为解决遮挡而暗改成 visibleFrame／rcWork，也不能擅自将窗口设成压过所有系统 UI 的极高层级。先在两端原生预览记录遮挡；如确实影响晕眩可见性，再将「使用工作区作地面」作为明确可选设置或待用户决定项。顶部菜单栏和屏幕缺口同样记录实际可见性。

屏幕断开、排列或分辨率改变时取消旧房间仿真，选择仍可见的屏幕，将实体最小位移回收并清除不再有效的速度。DPI 改变保持角色锚点和输入坐标连续。缩放改变、收起、退出、休眠和失去鼠标捕获分别有取消路径，不遗留定时器、抓取态或离屏角色。保存位置发生在停稳／恢复后的稳定位置，不在每个物理帧写配置；重启后不恢复半段飞行或过期速度。

| 片段 | 表演与驱动 | 首轮时间设计 |
| --- | --- | --- |
| airborne | 松手保留姿态与倾斜；身体、头颈作为整体，不单独晃头；衣摆／手臂允许小幅滞后 | 持续时间由物理决定；动作循环不能自带向前飞的位移 |
| wall-impact | 面向实际法线的一次短促收紧／闭眼，身体惯性稍滞后 | 约 80–140 ms；强度取碰撞前法向速度 |
| landing-impact | 脚底贴地、局部屈膝和衣摆延迟；从接触到最深缓冲，再恢复；若物理回弹则随其运动 | 约 160–240 ms；0/40/80/140/220 ms 可作为首轮关键点 |
| dizzy-intro | 稳住脚后露出发懵表情，星星出现 | 约 120 ms |
| dizzy-loop | 整体以脚底为支点轻微左右失衡，头颈保持整体关系；半垂眼／轻微失焦；三颗小星星在头上绕椭圆，前后遮挡正确 | 循环约 0.9 s，整体倾斜约 ±3°；由晕眩总时长控制退出 |
| recover | 星星淡出、身体归正、表情恢复，接最新工作状态 | 约 300–450 ms |

这套具体表演是为雪绪拟定的设计，并非 Pixar 或其他角色的已公开数据。优先通过新部件的局部姿态表达落地缓冲；禁止全图粗暴挤压，把脸、描边和原比例一起拉坏。衣摆动作不得暴露原画中被遮挡的身体区域或改变服装覆盖。

晕眩不是简单播放现有 failed 动画，也不是在静止人物头上贴几个星星就算完成。原尺寸下至少应读出「撞击后的缓冲 → 失去平衡／眼神发懵 → 恢复」三段。轻放仍有短而清楚的晕眩，避免只调一个看不出的强度。

强度先取 q = clamp((impactNormalSpeed - 120) / (1200 - 120), 0, 1) 作为调试起点，再以曲线映射局部幅度和时长。不要使用碰撞后的速度计算强度，也不要让每次接触都重置晕眩计时。落地段和星星保持适度，不做全屏震动、闪白或新增音效。

眼睛优先沿用 gaze_layers.py 的思想：虹膜、瞳孔、高光作为整体在固定眼框里移动，双眼同一位移及限幅，眼白补底，眼角、睫毛和开口固定。held 目前没有眼皮 rig，必须为新角色姿态实际标注，不能套用工作动作的坐标。需要独立眼皮时按现有六级覆盖机制接入；特殊闭眼表情优先于普通眨眼，基础 BlinkClock 继续前进，恢复后不补播积压眨眼。

每段输出：唯一帧、sequence、durationsMs、是否循环、loopStart、内容锚点、脚底点、重心、碰撞轮廓、部件枢轴、参数曲线、允许变化区域及来源哈希。时间以毫秒显式保存；碰撞发生在哪一时刻与图集多少帧相互独立。可按 50 fps 烘焙局部动画再合并重复帧，不能把全部飞行路径烘成固定视频。物理变化和衣摆／星星程序化变换可以连续渲染，但都必须可复现和可录制。

常规状态 192×208 与交互状态 192×240 切换时，用已记录的世界脚底点／重心对齐，而不是沿用窗口左上角。恢复到桌前动作时也需明确落地基线与内容锚点；不允许桌子突然悬在半空、角色忽然矮一截或瞬移。若需要过渡姿势，以同源局部制作完成；重叠淡化两张不对齐人物造成双影不算修复。

6. 100% 和至少 200% 实际打开检查；数字通过仍不代表选对语义或描边干净。小星星可单独绘制成同风格矢量／图层，不必对程序绘制的图形跑 SAM，也不能拿三个星星不连通作为角色蒙版失败。

8. 全部几何变换和合成遵守预乘 alpha，导出时明确编码约定。眼皮替换包含 alpha；不得把半透明头部重复叠到原头像上造成粗边。

**10. 两端集成与性能要求**

- 调整 PetView 的输入回调及 Windows 消息处理，明确 capture loss／取消事件；透明区域照常点击穿透，角色正在飞也能命中其变换后的实体，星星默认不拦截桌面点击。
- 交互层覆盖角色画面期间，后台任务路由、回答、提醒继续正确运行。任务气泡可暂时收起以免高速跟飞；已经打开的问题／回答卡保持可用并固定在可见位置，不能清除用户输入或吞掉待回答问题。交互完成后按最新状态恢复布局。
- 保留不抢焦点、右键设置、收起、托盘／菜单栏和多屏回收行为。安全退出交互时不能误触发聊天跳转。
- 物理 120 Hz，飞行／撞击期间绘制目标 60 Hz，静止回到原更新节奏；支持显示器更高刷新率时另测。定时器用实际经过的单调时间；原业务轮询保持原频率，不以 tick 次数变化造成成倍查询。
- 不每帧重解码大图集，不每帧重新分割或做昂贵图像生成。缓存限定内存；新动作冷启动时可预热小量帧，不能解码整套几百 MB 素材。Windows 旋转合成成本要原生测量。
- 新动作同步修改两端 catalog、读图、眼皮、分页准备和资源校验逻辑。先审查 YukioWin/scripts/prepare-windows-assets.py 对新 manifest 的支持；不假定旧分页脚本会自动包含 interaction 资源。分页与母图集解码像素一致，源 manifest 哈希匹配。

**12. 必须覆盖的验收场景**

物理自动测试使用可控时钟和共享 fixture，断言行为与不变量，不能只照抄实现公式自证：

- 向左、右、上、下及斜抛；慢拖、快速甩、最后反向甩、停住 150 ms 再释放、只有少量事件、相同时间戳和极端样本。纯点击不抛。
- 静止从已知高度下落，与解析落点／时间近似一致；同一输入以 30/60/120/144 Hz 渲染回放，在相同仿真时刻输出相同轨迹。
- 四面墙、高速撞角、贴墙释放、初始局部越界、极小可用空间；无 NaN、无穿墙、无重复接触风暴，无碰撞自增能。屏幕过小容不下角色时进入明确的缩放／回收降级路径，不让上下界倒置。
- 地面支持、横向滑动减速、低速不回弹、最终停稳。单次接触强度取碰撞前速度；多次回弹不反复重置完整晕眩。
- 空中最高点 vy≈0 时不能判定落地；侧墙／顶墙不能触发站立晕眩；在地面放下零高度角色也能安全完成轻反应。
- 每个交互阶段重新抓取与重新释放；抓取后旧速度、旧样本、旧碰撞事件不能污染新一轮。松手转重心枢轴不得跳位置。
- 负坐标副屏、100%/150%/200% DPI、用户角色缩放、跨屏拖动、拔屏、休眠唤醒、缩放中断、隐藏显示、丢失鼠标捕获与关闭开关。
- 活动状态在空中／晕眩时变化，恢复到最新状态；待回答卡与未发送输入不丢失；重启时角色仍可见。

量化标准作为本任务验收目标，需区分仿真与系统显示误差：纯逻辑两端相同 fixture 的位置差 ≤0.5 逻辑单位、事件时刻差 ≤一个物理步；无背景干扰的原生录屏中显著不透明轮廓越墙／穿地 ≤1–2 逻辑单位；接触基线不因透明 padding 产生肉眼可见悬空。超标查原因，不先放宽阈值。

视觉验收包括轻／中／重三档，所有新片段至少三个完整播放，观察手、腿、衣摆、脸、头颈、星星遮挡和连续切换。重点看脚底接触、无重复轮廓、无锯齿色边、无突然变脸变比例、无眨眼残片、无落地后窗口回跳。原尺寸不看标签应能认出晕眩。

原生验证沿用已存在的 --check、--snapshot、--blink-snapshots；本次涉及性能，应运行 --motion-benchmark 并增加交互路径的帧耗时与内存测量。新动作若尚未纳入这些诊断，先扩展检查入口。拟新增的轨迹 replay／interaction snapshot 参数必须先实现，不能把未存在的命令写成已跑过。

分别记录机器、系统、屏幕、DPI、资源哈希、源码状态及测试日期。macOS 成功不代表 Windows 通过；Python 纯逻辑测试也不代表 Windows 的分层窗口、捕获、DPI 或绘制已验证。
