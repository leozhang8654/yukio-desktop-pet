# 千夏——现代科幻风桌宠动画方案

这是当前设计方向，替代早期的温馨书桌风格。**现有 12 种 AI 工作状态，每种提供 5 个方案，共 60 个。** 文末另列拎起、抛掷等 7 个互动阶段，每个阶段也提供 5 个方案。这些是供选择的备选设计，不代表需要制作随机切换系统。

## 整体画风

保留参考图中千夏的发型、发饰、服装和配色。为她搭配一张小巧、圆角的白色与深灰色控制台，点缀薄荷绿／青色灯带和粉色按键。科技道具保持可爱且有实体感：大颗粒按键、短粗触控笔、兔子造型设备，以及适合宽大袖口的小控制器。

人物和控制台组成紧凑的桌宠轮廓，外围透明。背景细节限于桌宠范围，不加入房间、墙壁、城市景观、大平台或大面积悬浮界面。

人物约占画面高度的 85%–90%。装饰控制在三四组：停在底座上的兔子设备、桌下两个卡匣式存储盒、小充电盘或折叠耳机，以及融入家具的贴纸、散热孔和一根短线缆。每个状态只使用一种主要工作道具。投影式界面紧贴桌面上的小底座，高度低于脸部，不遮挡状态气泡和真正的问题卡片。使用大而简单的图标，不依赖微小文字传达信息。

此前生成的图片只用于参考人物形象和紧凑构图，不代表本次科幻风格。本次修订没有生成新的插画或动画。

## 沿用现有动画方法的边界

十二种工作状态全部按现有部件蒙版合成方法设计：头、颈、身体、家具固定；一到两组手与道具做小幅运动；手腕连接端固定；移动后露出的区域预先补底；双眼共用视线限幅；六级眨眼独立播放。握持道具与握住它的手作为一组移动。

道具在源图中就已握好、摆好或放入底座。动画不表现抓取、换握、插入、拔出或松手等复杂过程。

“全息感”通过半透明绘制和固定光晕表现。键盘投影、屏幕内容、图标、光束和高光保持静态，不制作动态照明。不需要透视翻转面板、三维旋转物体、逐渐出现的笔迹、翻页、线缆模拟、粒子系统或独立活动的机器人。道具只在画面平面内做小幅平移或旋转。旋钮随手部仅摆动几度，具体连接点和接触关系仍需制作时验证。

使用 384×416 像素源图，按 192×208 点显示。第一轮沿用现有时间数组、循环入口和状态含义。手部位移可从 0.5–2 点、旋转从 1–3 度开始调试；这些是制作建议，不是已验证的千夏参数。

千夏仍需单独制作源图、蒙版、补底、眼睛定义和各状态参数。现有代码中雪绪专用的硬编码连接点、输入路径等也需要配置化。沿用同一种技术，不等于把新图直接替换进去就已能正确播放。

## 每种工作状态的 5 个方案

### 1. 空闲——`idle`

含义：当前没有正在处理的任务。

1. **兔子机器人作伴**：轻轻拍一下停在底座上的小兔子机器人，然后长时间放松停留。
2. **充电盘旁发呆**：靠着小充电盘休息，指尖沿盘沿轻轻划过一小段弧线。
3. **磁吸小玩具**：手里握着磁吸圆片，在袖口旁小幅晃动几度，然后停下。
4. **耳机休息时间**：耳机已经戴好，手轻轻调整一下耳罩，目光缓缓看向用户。
5. **智能杯小憩**：两只宽袖围着带温度显示的小杯子，一只手轻轻靠稳杯边，随后保持安静。

### 2. 思考／规划——`thinking`

含义：推理、比较和制定计划。

1. **节点图推演**：下巴靠在固定袖口上，视线在半透明规划面板的两条分支间切换。
2. **停在脸旁的光笔**：握着发光笔尖的短笔停在脸旁，眼睛向上看，停顿后看回控制台。
3. **逻辑拼片**：手里已经握着电路拼片，朝匹配槽位轻推一点，犹豫后缓缓退回，全程不松手。
4. **环形规划图**：双手保持交叠，目光依次查看固定环形面板上的三个标记。
5. **双色决策芯片**：青色和粉色芯片放在托盘里，手指犹豫地轻点一次，再用目光比较两者。

### 3. 读取文件——`read_file`

含义：查看本地文档、代码或其他文件。

1. **数据卡匣阅读器**：卡匣已经插好，手指沿小型文档屏幕上的一行内容慢慢划过。
2. **电子墨水档案板**：拿着薄电子纸板，阅读用的手指沿固定文字列缓慢向下移动。
3. **透明档案卡**：手中半透明数据卡轻轻摆动，视线依次检查标题和下方条目。
4. **条形代码阅读屏**：短指示笔沿桌面窄屏的一行代码移动，停顿后回到起点。
5. **层叠文件标签**：三块透明文件面板固定排成扇形，手指与目光依次查看各自的编号标签。

### 4. 查看图像——`view_image`

含义：检查图片中的内容和细节。

1. **发光扫描镜**：方形发光放大镜与握持手一起，在检查垫上的固定缩略图上小幅扫过。
2. **全息照片卡**：拿着带发光边框的图片卡，在画面平面内微微倾斜，目光检查相对的两个角。
3. **透光检查台**：触控笔在透光台的图片上划一小段检查弧线，停在某个细节附近。
4. **双图对照屏**：小型双屏各显示一张缩略图，目光左右比较，一根手指指向其中一处角落。
5. **构图取景框**：握着发光矩形小框，在固定图片上方轻轻挪动，像是在检查构图。

### 5. 编写／修改文件——`write_file`

含义：创建或编辑内容。

1. **光笔编辑板**：在深色玻璃板上快速写三个短笔画，停顿后回到起点。
2. **投影键盘**：桌面小投影条映出固定的青色键位，双手交替做短促的小幅打字动作。
3. **分体键盘控制台**：双手在两个小键区上以不完全同步的节奏打字，每一小段后明确停顿。
4. **代码修订笔**：用短粗编辑笔沿竖立屏幕上已经高亮的代码块描过两小段。
5. **符号输入板**：一根手指依次点三个相邻方键，停一下，再以略有变化的节奏重复。

### 6. 测试／验证——`verify`

含义：检查结果，但不提前表示测试已经通过。

1. **诊断探针**：手持探针轻轻靠近测试触点，停下来查看仪表，再抬起一点。
2. **波形对照**：视线和指示手在两条固定波形间切换，在对齐标记处停顿。
3. **扫描棒检测**：手持扫描棒在测试模块上缓慢扫过一小段，停顿后返回。
4. **测试按钮台**：按一下大测试键，保持安静并观察中性指示灯，然后手部回位。
5. **校验码检查板**：短指示笔依次查看三个校验格，在每个空结果框旁停留片刻。

### 7. 浏览网页——`read_web`

含义：从网络查找外部信息。

1. **地球图标终端**：在带地球图标的浏览板上连续做两次短滚动手势，停一下，再点标签。
2. **网络节点图**：小屏幕显示固定的连接节点，指示笔访问两个相邻节点，视线跟随。
3. **搜索触控板**：手在触控板上小幅滑动并点击，目光看着带放大镜标识的搜索屏。
4. **扇形链接面板**：三块浏览面板固定悬在小投影底座上方，手指交替指向其中的链接图标。
5. **信息流旋钮**：手轻轻拨动实体浏览旋钮几度，停下来查看固定信息流，再缓缓回位。

### 8. 其他工作——`default_work`

含义：构建、执行命令和其他未单独分类的工具活动。

1. **迷你命令台**：在紧凑终端前快速敲几下键，再小幅调整鼠标手。
2. **双手控制台**：两只袖口中的手以不同节奏点击各自的按钮，之后留出较长观察停顿。
3. **轨迹球操作**：手在固定轨迹球上做克制的小圆周动作，目光留在工作屏上。
4. **构建模块台**：按下计算模块旁的实体执行键，再观察固定的中性状态条。
5. **触控条操作**：一根手指沿控制条横向滑一小段，停顿后点一下末端按钮。

### 9. 整理／输出回答——`respond`

含义：把答案展示给用户。

1. **结果平板**：双手已经拿着朝向用户的结果板，轻轻向外推一点，然后稳稳保持。
2. **消息胶囊**：将手里带消息图标的数据胶囊朝桌沿轻推一点，保持握住并停留。
3. **全息报告框**：轻轻抬一下手中的半透明报告板，摘要图形从开始就清晰可见。
4. **电子明信片**：用一个小幅手腕动作展示发光消息卡，然后停稳。
5. **结果屏展示**：结果屏已经朝向用户，手在消息图标旁做一次小指示动作，随后放松。

### 10. 任务完成——`task_complete`

含义：任务已完成，等待用户查看或确认。

1. **兔子勾选灯牌**：拿着兔子造型的发光勾选牌，小小地得意抬起一次，然后持续展示。
2. **完成提示控制台**：桌面控制台已经显示大勾，手指在旁边点一下，然后停住。
3. **星形能量奖章**：展示带醒目勾号的发光星形小核心，轻轻向上托一下。
4. **完成通行卡**：手中已拿着任务完成卡，稍稍朝用户倾斜，保持标识可读。
5. **小小胜利握拳**：固定的大勾屏旁，两只小拳头克制地抬起庆祝一次，然后放下停稳。

### 11. 等待用户回答——`question_for_user`

含义：等待回答、选择或授权。

1. **选择控制台**：两个大选项块上方显示问号，手指缓慢地交替指向两块，然后等待。
2. **问号平板**：拿着半透明问号板，小幅抬一下引起注意，随后安静保持。
3. **访问权限申请**：手里已经拿着带锁和问号的访问卡，轻轻递向用户并等待。
4. **呼叫按钮**：在问号标识下方的桌面通讯按钮旁轻点两下，然后保持不动。
5. **耳机等待回应**：手停在已戴好的耳机旁，目光看向用户，旁边的小问号面板持续可见。

### 12. 失败／出错——`failed`

含义：工具或任务遇到错误。

1. **断开的连接头**：线缆插头在源图中就已断开，握着插头的手轻轻下落一次，视线随之低垂。
2. **错误控制台**：手指停在带明显错误符号的控制台上方，稍稍退回，然后保持安静。
3. **故障数据卡**：略斜地拿着错误标记数据卡，双手停稳，脸上保持预先画好的小委屈表情。
4. **中止的诊断**：检测棒已经握在手里，在警告模块旁微微放低，然后停住。
5. **传输受阻**：固定屏幕显示传输中断符号，鼠标手停止动作，稍稍后撤并保持。

## 状态含义与节奏

- 空闲多停留，思考多用目光停顿；读文件慢慢描行，写文件短促连续，浏览网页采用“滚动—停顿—点击”，测试采用“检查—等待—观察”。让各状态有不同节奏。
- 验证阶段使用中性指示灯和空结果框，不虚构通过或失败。醒目的成功勾号留给任务完成。
- 输出回答的开场动作应在现有约三秒的响应展示时间内完成。任务完成只做一次强调动作，之后持续保留完成标识。
- 等待状态持续显示问号，安静地等用户。装饰道具不编造真实问题选项，也不替代现有交互问题卡。单纯拒绝权限不应进入失败状态。
- 失败只做一次小幅沉落，之后保留错误标识。不反复惊慌、不持续闪警报，也不通过修理动作暗示错误已经解决。
- 每个状态的嘴型和眉形预先画好；状态内的表情变化依靠已有目光和眼皮机制，不预设嘴部动画。

## 拎起与抛掷：每个互动阶段的 5 个方案

这些是临时覆盖当前工作动作的物理互动，不属于 AI 工作状态。复用现有拎起、抛掷物理与互动渲染器，为千夏单独制作源图层、抓取点、碰撞几何和接触锚点。

被拎起时使用纯人物素材，桌子、屏幕、线缆、机器人配件和装饰不跟着飞。互动渲染器已有整体飞行、反弹和摇晃能力；这不改变十二种书桌工作状态中头颈固定的要求。

下表五列分别是一套连贯的表现风格。眩晕图标沿用现有星星的轨迹、时序和遮挡，仅更换造型；仍需检查新蒙版、补底和视觉效果。撞墙与落地保留现有轻、中、重三级反应规则。项目记录中的本地抛掷功能仍标为未发布，Windows 原生验收待完成。

| 阶段 | 方案 1：操作员 | 方案 2：技术员 | 方案 3：驾驶员 | 方案 4：导航员 | 方案 5：兔子吉祥物 |
|---|---|---|---|---|---|
| 被拎起 `held` | 收起双手，预先画好的睁大眼惊讶表情。 | 固定半垂眼，像困困地被提起来。 | 小鼓嘴、手肘收紧。 | 专注的固定表情，双手对称收好。 | 固定浅笑，鞋尖略朝内。 |
| 空中飞行 `interaction_airborne` | 惊讶姿势跟随现有位移与旋转。 | 困倦姿势跟随现有位移与旋转。 | 鼓嘴紧凑姿势跟随现有位移与旋转。 | 警觉姿势跟随现有位移与旋转。 | 吉祥物姿势跟随现有位移与旋转。 |
| 撞墙 `interaction_wall-impact` | 小幅回弹，预先画好的眯眼。 | 小幅回弹，预先画好的受惊脸。 | 小幅回弹，预先画好的鼓腮。 | 小幅回弹，预先画好的紧闭眼。 | 小幅回弹，预先画好的漫画式小皱眉。 |
| 落地 `interaction_landing-impact` | 鞋子撑稳，沿用落地压缩。 | 双脚靠近，沿用落地压缩。 | 袖口收紧的落地姿势，沿用压缩。 | 对称整齐的落地姿势，沿用压缩。 | 柔软紧凑的落地姿势，沿用压缩。 |
| 开始眩晕 `interaction_dizzy-intro` | 切换到预制发懵表情，开始现有摇晃。 | 切换到预制困倦发懵表情。 | 切换到预制鼓嘴发懵表情。 | 切换到预制疑惑表情。 | 切换到预制漫画式晕乎表情。 |
| 眩晕循环 `interaction_dizzy-loop` | 青色像素十字沿现有星星轨迹移动。 | 粉色电池轮廓沿现有星星轨迹移动。 | 青色断环图标沿现有星星轨迹移动。 | 紫色警告菱形沿现有星星轨迹移动。 | 粉色兔脸图标沿现有星星轨迹移动。 |
| 恢复 `interaction_recover` | 现有摇晃收稳，回到实际任务状态。 | 摇晃收稳，以平静的源图表情恢复。 | 摇晃收稳，短暂保留固定小鼓嘴。 | 摇晃收稳，以专注的源图表情恢复。 | 摇晃收稳，以柔和的源图表情恢复。 |

## 建议先选的一套组合

兔子机器人作伴 → 节点图推演 → 数据卡匣阅读器 → 发光扫描镜 → 光笔编辑板 → 诊断探针 → 地球图标终端 → 迷你命令台 → 全息报告框 → 兔子勾选灯牌 → 选择控制台 → 断开的连接头。

这套组合共用小控制台和角色造型，通过明显不同的工具与节奏区分状态。每个状态选中的道具替换桌面中央的工作工具，不会永久堆积在场景中。

## 制作状态与依据

本次仅制作设计方案，没有修改动画源素材、正式资源、应用代码或已安装的 App，也没有宣称动画已通过验收。源图、蒙版、透明边缘、循环和原生播放的详细验收要求继续参照项目 AGENTS.md 与[前一版技术说明](README.md#production-handoff-for-the-selected-options)。其中早期温馨风格和每状态三个方案的选择范围，以本文件为准。

状态依据：[macOS Events.swift](../../../YukioPlayer/Sources/YukioCore/Events.swift)、[Windows events.py](../../../YukioWin/yukio/events.py)。动画方法：[approved_motion.py](../../../YukioPlayer/tools/motion/approved_motion.py)、[已验收输入格式](../../../sources/approved-animation-rig/README.md)。互动格式：[动画格式说明](../../animation-format.md)。

这里的科幻道具和表现细节均为基于用户角色参考图提出的原创设计，不作为游戏官方设定陈述。对应英文版见 [sci-fi-designs.md](sci-fi-designs.md)。
