# 千夏动画独立检查要求（大白话版）

本文件根据已有千夏底图任务书、动画设计方案、用户反馈及独立返工记录整理，供后续检查人直接使用。这是一份检查要求，不是本轮动画已经通过的报告。

## 1. 检查人的任务

判断这套千夏动画是否保留已确认的设计、在桌面实际大小下看得清、动作合理、长时间观看舒服，并找出具体问题。

检查人必须是没有参与本轮制作的另一位检查者。制作方可以提供原图、候选、对照和本要求，不能用“我们已经检查过了”“应该能通过”代替独立判断。检查人先看原图和动画，再核对程序检查结果；复审可以先读自己上次的问题清单。

检查期间不修改候选；有问题就留下证据交回制作方。修好另存一轮，再检查。制作方不能代写、改写独立检查结论。

## 2. 开始前确认检查的是哪一版

- 写清候选轮次、十二个状态的文件、实际使用的预览，以及对应的已确认原图。
- 确认预览播放的就是本轮文件，不能拿旧预览替新文件过关。文件核对信息附在报告后面即可，不要求用户读懂。
- 送审后不要一边检查一边覆盖文件。候选发生变化，就记录变化并重新检查受影响部分。
- 已有的静态通过只证明当时检查过的内容；不自动证明移开后的底图、运动接缝或动画已经通过。
- 判断优先使用用户最新明确反馈，其次是最新任务书和已确认底图，再参考旧方案。早期废弃建议不重新变成要求。

## 3. 先守住已经确认的设计

保留同一位千夏的脸、发色、发饰、服装、比例、画风与安静气质。保留科幻设备及其工作含义：思考问号、三张文件卡、扇形多面板、检查笔、分体键盘、诊断探针、轨迹球、电子明信片、完成后的趴桌姿势与对号。

思考和等待回应都可以有问号。设备和符号允许成为画面重点。检查人不能为了自己更喜欢的构图，要求删掉问号、把多屏合成单屏、把探针换成清单，或把遮住的脸强行露出来。

任务气泡负责解释准确工作内容。检查人物、设备、动作和真实气泡是否协调；无文字观察只作辅助，不能以“猜不出全部十二种状态”为由推翻已确认的设计。

## 4. 所有动画都要过的检查

1. **该动的地方，在实际大小下看得见。** 按桌面实际的 192×208 显示大小、正常速度观看；正常坐姿下，专门看动作时能发现她正在做什么。只有放大数倍才看见的工作动作需要返工。完成状态有意静止，思考和读文件主要靠眼神，不要求它们额外晃手。旧方案的幅度是起点，不是必须守住的上限。
2. **看得见，也不能晃得烦。** 头颈、身体主体、头发、蝴蝶结、桌椅、脚、摆件及设备底座保持稳定。不能靠整个人起伏、桌子晃动、整块屏幕闪光来增加存在感。该停时真正停住。
3. **动作有目的、有停顿。** 打字是几下短敲后停顿，阅读会停留，检测要等一等。不能十二种状态都匀速左右摆，也不能用随机抖动冒充自然。
4. **手确实连着身体，拿得住东西。** 手与笔、探针、卡片一起动；指尖确实按到目标；手掌操作轨迹球时保持接触。动作最大时也不能断腕、脱握、穿过设备、拉长手指或把固定底座一起带走。
5. **移开后露出的地方也画对了。** 手或卡片移开后，袖子、衣服和桌面要接得上，不能露出黑碎片、洞、第二只旧手、旧笔杆或重复轮廓。首帧好看不算过关。
6. **眨眼从开始闭合到重新睁开都自然。** 睫毛不能突然变细或换形，眼角不能乱跳，眼白不能碎成小台阶；闭上后不能漏出彩色眼珠。双眼看同一个目标，不各看各的。眨眼不跟每次敲键、每次换状态机械同步。
7. **重复和切换没有跳一下。** 一轮结束回到开头时，手、道具和眼神不能突然弹回。换状态时公共桌椅位置稳定，不出现双脸、双手、闪白或旧动作残留。完成的趴姿属于有意变化，不能强求与直立姿态同轮廓；也不能把直立图硬压扁成趴下过程。
8. **边缘在不同背景下都干净。** 分别看白、黑、洋红、棋盘格背景，检查手指、探针尖端、细笔杆、袖口和头发边缘。保留原本透明的投影、光晕和真实空隙；不能统一描白边或抹糊来遮错。
9. **画面不谎报工作结果。** 验证中不能显示“全部通过”；回答不自动冒充任务完成；等待不能反复催促；失败不能自行庆祝恢复。信息要随真实状态变化，不能为了播完整段动作拖住重要提示。

## 5. 十二个状态逐项看什么

| 状态 | 应当看到 | 出现这些就退回 |
|---|---|---|
| 待机 | 手轻拨悬浮球，球随后微晃并收住，大部分时间安静 | 手还没拨球先响应；球持续弹跳；底座跟着飘 |
| 思考 | 托腮保持不动，眼神在少量节点之间看一会儿、停一会儿 | 点头揉脸；眼珠匀速巡航；问号持续跳动 |
| 读文件 | 三张卡和双手稳定，目光按顺序阅读并停留 | 文件卡飞进飞出；为了表现阅读而让整个屏幕扫光 |
| 看图片 | 手和检查笔一起指向细节，停看后再小幅换位 | 连续划线像在画画；笔脱手或跨越够不到的地方 |
| 写文件 | 两手错开短敲，成组动作之间有停顿 | 等间距左右敲成节拍器；整条袖子或键盘一起升降 |
| 验证 | 探针接近触点、保持检测、抬起，再观察 | 针尖滑过或扎穿模块；只有连敲没有等待；提前显示成功 |
| 浏览网页 | 看目标面板、点一次，再停下来阅读 | 不停戳屏；投影和符号反复翻转、弹跳 |
| 工作中 | 手贴着轨迹球微调，停下看屏幕，再做小调整 | 手离球后仍作操作动作；球像待机玩具一样不停晃 |
| 回答 | 手和卡递出一次，然后稳稳拿着 | 反复收回递出；持卡持续抖动；袖口露出暗碎片 |
| 完成 | 埋头趴桌保持静止，对号稳定清楚 | 增加眼睛、抬头、打呼、呼吸缩放或反复趴下 |
| 等待回应 | 按按钮一次，随后安静等；问号稳定 | 同一个问题反复按铃；问号闪烁催促；整个按钮底座下沉 |
| 遇到问题 | 故障卡轻提一次后稳定持住，保留温和失落表情 | 同一条失败信息反复举卡；哭泣、爆炸、全屏红闪 |

## 6. 实际怎么检查

先看写文件、验证、等待回应，确认三种节奏确实不同，再覆盖全部十二个状态。这只是检查顺序，不能以三个样本代替整套。

- 使用本轮最终保存的动画文件重新打开播放，不能只看制作过程中的效果。
- 前八个循环状态：每个按实际大小、真实速度连续看至少三轮，必须看见循环交界。随后放大至少两倍、慢放和暂停，检查手腕、接触点、最大位移、眨眼及透明边。
- 回答、等待回应、遇到问题：分别检查首次进入、长时间保持、同一事件重复刷新、真正的新事件。前两类刷新不能重新举卡或按按钮，新事件才可以重新提示。
- 完成：检查持续静止与进出状态，不要求不存在的身体循环。
- 连续切换状态，检查公共场景是否跳动、是否残留上一个动作、眨眼是否每次都重来。
- 配合真实任务气泡检查遮挡和含义。只有示意图时，写明“真实界面未验证”。预览测试不能冒充正式 App 已测；Mac 实测不能冒充 Windows 实测。
- 长时间观看要检查是否抢注意力。本版为方便执行，建议给三个一次性状态和完成状态各留至少一分钟，另做五分钟混合观看；这是新增的建议时长，不是旧文件已有数值，也不能替代重复刷新和新事件的实际测试。

检查人必须亲自看到连续播放。截图能证明某个画面，不能证明节奏和长期保持；播放计数、文件核对、编译成功也不能证明已经看过动画。窗口没播、被挡住而看不到或工具受限，就如实记未测。

## 7. 怎么下结论

逐项只写：通过、失败、未测、不适用。每个状态单独列结果。

必查项全部完成且没有必须返工的问题，才能给整套“通过”。存在失败或必查项未测，整套就写“退回”，并分清“已发现缺陷”和“还缺验证”。范围外的安装、发布及平台测试单独说明，不凭空扩大成本轮义务。

动作在实际大小看不见、破坏确认设计、接触断裂、残手露洞、眨眼破相、固定场景乱动、一次动作反复触发、循环明显抽动，都属于必须返工。不能用总分高或“只有几个像素”抵消。

每个问题要说清：哪个状态、哪个部位、什么时候出现、看到什么、为什么不符合要求、证据在哪里、修后要复查什么。别只写“不自然”“还可以优化”。

填写示例（沿用历史问题说明记录方式，并非宣布它仍存在）：

> 回答状态，递卡约0.8秒、卡片接近最远位置时，左侧袖口里露出一块悬空黑片。退回。证据附该时刻截图和位置圈注。修后重看整段递卡、最大位移及持卡停留，确认没有新接缝。

修复后检查原问题和周边是否出新问题。复用旧结论必须确认文件确实没变，并注明哪些沿用、哪些本轮亲自看过。用户指出漏检时，保留旧报告并追加更正，不能因为旧报告写了通过就忽略新证据。

独立检查通过后仍交用户验收；这不自动代表获准替换桌面 App 或发布。
