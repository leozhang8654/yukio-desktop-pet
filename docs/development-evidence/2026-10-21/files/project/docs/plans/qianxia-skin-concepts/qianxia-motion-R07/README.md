## 这轮改了什么

**1. 眨眼卡顿。** 查到四个原因，都已处理：

- **预览页每帧重画全部画面。** 对照页每个显示帧都把 24 个画面整张重画。在图集需要重新解码时，一轮实测约 39 ms，相当于每秒不到 25 帧；而一次眨眼总共只有十几帧。现在只在画面真正变化时重画，眨眼时只重画眼睛那一小块，预热后一轮的脚本耗时约 0.04 ms（不含 GPU 合成）。
- **图集被浏览器临时丢弃。** 对照页解码后的图集约 620 MB，浏览器会丢掉久未使用的大图，眼皮图集只在眨眼时才用，于是每次眨眼开头都可能要重新解码。现在加载时一次性解码成常驻位图，并在播放前把眼皮图集预热一遍。
- **只有 6 级眼皮，每级跨度大。** 改为 12 级，每一级下移的距离减半。正式 App 的眨眼时钟本来就按资源里的 `levels` 读取，所以 12 级也兼容。
- **眨眼第一帧睫毛"换了一副"。** 原来睫毛一动就从原图的酒红到深蓝渐变变成一整块纯色，看起来突然变粗。现在下移时保留原图的睫毛颜色；只有靠近虹膜、偏青或偏黄的边缘像素仍用睫毛墨色，保证全闭眼不带虹膜颜色。

另外，两个预览原来用的眨眼曲线和正式 App 不一样（直线、向上取整）。现在都改成正式 App `BlinkClock` 的曲线：先平滑闭合、短暂停留、再平滑睁开，双眨概率也一致。

**2. 回答、遇到问题不再有手部动作。** 手和卡片完全保持原图（检查确认眼睛区域以外 0 改动）。只保留一次目光变化：回答是从卡片看向你；遇到问题是先看卡片，再略向下地看向你。如果目光也不要，告诉我即可。

**3. 等待回应改为循环，每 5 秒一次。** 看向你 → 看按钮 → 按下并停一下 → 松开 → 看回你 → 等到 5 秒再来。循环时长精确为 5000 ms。

**4. 循环时长取整。** 原来按每帧 33 ms 累加，各循环会比设计短一点（例如 5 秒变成 4.98 秒）。现在差额补进最长的停顿，所有循环时长都等于设计值。
