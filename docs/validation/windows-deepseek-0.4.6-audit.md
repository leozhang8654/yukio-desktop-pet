## DeepSeek / Deep Code

[专项测试第一轮](https://github.com/leozhang8654/yukio-desktop-pet/actions/runs/38522465226) 与[复测](https://github.com/leozhang8654/yukio-desktop-pet/actions/runs/38526975579) 的已通过部分：

- 从公开包内安装入口，实际下载并构建固定版本 Deep Code，生成 Windows 启动入口，运行帮助命令成功。
- 公开程序读取隔离的 Deep Code 会话与索引数据，依次显示思考、读文件、看图、写文件、验证、读网页、其他工作、等待回答、失败、回答、完成和空闲，共 12 种状态；恢复任务和中断回空闲也通过。
- 从原生问题卡提交中文选项，经包内适配器收到回执；没有为普通回答附加工具权限。
- 包内 5 项适配器测试全部通过，覆盖等待问题、已回答或无关消息、未连接、单次允许／拒绝、过期申请和自由文本不能授权。

批准窗口的首次点击测试有测试工具定位缺陷：隐藏的复制窗口返回 1×1 的控件尺寸，记录到按钮偏移 `[0.5, 0.5]`。测试已改成枚举实际原生窗口的按钮，并等待原生卡片事件完成派发；保留失败记录，没有放宽回执断言或修改公开程序。

[最终批准专项复验](https://github.com/leozhang8654/yukio-desktop-pet/actions/runs/38631522147) **成功**：

- 在完整申请窗口出现以前，没有写出任何批准答案。
- 点击允许后，仅向当前测试申请 `audit-only-1` 传递一次 `allow`；保留原计划模式，没有长期权限。
- 点击拒绝后，收到拒绝回执，状态为 `permission_denied`，未调用继续执行。
- 两项都收到包内适配器的实际回执，原生界面结束等待。该轮只重跑尚未完成的批准专项和包内适配器测试，连接安装及其他功能沿用前述已通过的相同公开包结果。

## 适用边界

- DeepSeek 回答与批准往返使用受控 SessionManager 测试对象，验证真实 Windows 程序、包内适配器和本地回执通道；没有调用真实模型、执行测试申请中的命令或使用用户的密钥。
- DeepSeek 连接需要 Node.js 22+、Git 以及用户自己的模型配置。已有普通终端会话不会自动被接管，需从生成的入口启动连接会话。
- DeepSeek 在线模型、网页／插件中的真实账号交互、所有浏览器与多屏组合尚未端到端验证。因此不能将这些结果写成“Windows 所有场景全部正常”。
