# Yukio 助手：从提醒开始

现在的定位是「一个可以慢慢个性化的个人助手」。App 是管理事情的主界面，桌宠是桌面上的一个入口和显示方式。提醒数据不依赖角色是否显示，也不依赖 AI。

## 已经能用的起步版（macOS）

- 浅色原生主窗口：首页、提醒、个性化、扩展。
- 单次提醒：新增、编辑、删除、到点弹出、提示音、稍后 5 分钟、确认完成。
- 本地保存；重启恢复；睡眠或退出期间错过的提醒，下次运行时补上。
- 助手名字、对用户的称呼、提醒音开关会自动保存。
- 右键桌宠、菜单栏「打开 Yukio 助手」、再次打开应用，都进入主窗口；原桌宠设置保留在侧边栏和菜单栏。
- 关闭主窗口会回到菜单栏驻留，提醒继续运行；真正退出后无法在原定时刻发出提醒。

这是本地提醒起步版，不是后台系统闹钟服务。不唤醒休眠的电脑，没有系统通知、重复提醒、开机启动、WidgetKit 小组件或 AI 调用。扩展页清楚标出规划中功能。现有 Windows 播放器尚未加入这套主界面。

## 运行

```sh
cd YukioPlayer
swift test
./scripts/build-app.sh
open build/Yukio.app
```

开发时也可运行 `.build/debug/YukioPlayer --assistant-only`，只显示主窗口；`--pet-only` 则只在启动时隐藏主窗口，提醒仍正常运行。不要同时启动多个使用同一提醒文件的实例。

要保留正在使用的旧桌宠，单独试用新窗口，可执行 `YUKIO_ASSISTANT_PREVIEW=1 ./scripts/build-app.sh`。产物是 `build/Yukio Assistant Preview.app`，有独立的应用标识，默认不显示第二只桌宠；主窗口内仍能打开桌宠设置。

提醒保存在 `~/Library/Application Support/Yukio/reminders.json`，原子写入成功后才更新界面。文件损坏时保留原文件并显示错误，不用空文件覆盖。测试可通过 `YUKIO_REMINDER_FILE` 指向独立文件。称呼和提示音设置使用应用的 UserDefaults。

## 接下来怎么长

2026-09-25 补充方向：以每日行程、可纠正的活动记录和个性化规则为基础，逐步发展条件提醒及兴趣简报。详见 [行程、活动记录与个性化助手设计](PERSONALIZATION.md)。这是设计方案，屏幕观察、AI 和自动记录尚未实现；下文保留现有基础能力的实施注意事项，整体开发顺序以新设计为准。

先做提醒的可靠性：每日/工作日重复、系统通知、通知权限状态、开机启动、时区和夏令时规则。系统通知由同一个提醒服务统一调度，避免窗口提醒与系统通知重复响。确认关闭窗口、退出进程、休眠、重新开机分别会怎样。

再做展示：桌宠旁的小提醒卡，以及只展示「下一件事」的小组件。它们都读取同一套提醒数据。WidgetKit 需要单独的扩展 target、App Group 共享存储和相应签名配置，不能把主窗口缩小就当作系统小组件。

之后接 AI：第一项能力只做「用一句话创建提醒」。模型负责把「明早九点提醒我出门」解析成结构化草稿，遇到不清楚的时间就询问；用户确认后仍走现有的提醒保存入口。AI 不负责计时。断网或模型出错时，手动创建提醒照常可用。

最后逐步增加个性化：先让用户明确选择语气和偏好，再提供可以查看、编辑、删除的记忆。API 提供方、地址与模型配置独立管理；密钥存 Keychain，不进入提醒文件、日志或普通偏好设置。接日历之前先做好权限和同步冲突规则。

每次只补一条完整的使用路径：一句话交代 → 看清将要发生什么 → 可靠执行 → 随时修改或取消。

## 代码入口

- `Sources/YukioCore/Reminders.swift`：平台无关的数据、状态转换和文件读写。
- `Sources/YukioPlayer/ReminderStore.swift`：共享可观察状态、计时、持久化和提示音。
- `Sources/YukioPlayer/AssistantWindow.swift`：主窗口、编辑表单、独立提醒面板。
- `Sources/YukioPlayer/main.swift`：挂接已有应用生命周期和桌宠入口。

未来 Windows、小组件、日历与 AI 应接到提醒服务，不把业务规则复制到各个页面里。接多进程写入前需要升级存储的并发协调方式。
