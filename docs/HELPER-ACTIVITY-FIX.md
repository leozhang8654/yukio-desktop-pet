# 协作任务仍在运行时的工作显示修复

2026-10-11，macOS 0.4.3 测试版第 21 次构建。

## 现场发现

用户报告另一条 GPT 聊天持续工作，雪绪却没有工作动作。实际看到雪绪举着一块只有编号的完成牌；仍有其他活动卡片。当前规则会优先显示未处理的完成牌，最长十五分钟。调查发现该聊天有协助助手，旧程序把协助助手结束误当成了一个需要用户查看的完成回答。

同一份协助助手记录同时包含父任务编号和自身编号。旧读取优先用了父任务编号；但大文件重启时只读末尾，又会使用文件名里的自身编号，导致身份不一致、显示无意义编号，并可能把协助助手结束误作用到父任务。

## 改动

- 优先使用协助助手自身编号，父任务关系单独保留；大文件只回放末尾前也先读取开头的身份信息。
- 协助助手执行时显示工作动作，名称关联到父聊天；协助助手向主助手汇报，不单独举完成牌。
- 明确的开始记录立即启动工作状态，不必等第一条回答或操作。
- 普通聊天的完成提醒、等待用户回答的提醒仍保留。
- 本机诊断增加当前动作、跟随对象和正在工作对象，方便区分“没读到工作”和“正在显示别的提醒”。

## 验证

203 项自动检查通过，包含四项新增检查：父子任务身份分离、协助助手结束不终止父任务且不举牌、普通聊天仍有完成提醒、大文件重启后仍正确识别协助关系及名称。

读取本机真实活动记录时，已能显示对应父聊天名称及协作标记。桌面安装后的实际结果另存本机检查记录；不把自动检查冒充现场动作验收。本轮没有声称所有 GPT 任务、远程任务或 Windows 实机均已通过。
